  Summary

  New abstractions (Appointments.API):
  - Interfaces/IClock + Helpers/SystemClock — "now" is injected everywhere,
  never DateTime.UtcNow inline in rule checks.
  - Interfaces/IDoctorsClient extracted from the concrete DoctorsClient (was
  previously a concrete class with only an existence-check method) — now
  GetDoctorAsync returns a DoctorInfoDto? { Id, IsActive }, fetched from
  Doctors.API's GET /doctors/{id}. This also let the available-slots feature's
  doctor-exists check consolidate onto the same method.
  - AppointmentCreateDto gained DurationMinutes — previously appointment length
  was hardcoded to 30 minutes, so there was nothing to validate; duration is now
  a real client-supplied value.

  Rules enforced in AppointmentService.BookAsync (config-driven via
  AppointmentRules in appsettings.json, defaults 15/120/30 matching the skill):
  1. Duration 15–120 min → ArgumentException
  2. Start time ≥ 30 min from IClock.UtcNow → ArgumentException
  3. Doctor must be IsActive → InvalidOperationException
  4. No overlap for the same doctor, strict </> comparison so touching
  boundaries are allowed → InvalidOperationException

  CancelAsync: previously only allowed cancelling from Pending, which
  accidentally rejected cancelling Confirmed appointments entirely (not what the
  skill's state machine says) while only incidentally blocking double-cancel.
  Rewrote it to explicitly reject cancelling an already-Cancelled appointment
  with its own message, and allow cancelling from either Pending or Confirmed —
  matching the skill exactly.

  Controller: BookAsync now catches InvalidOperationException → 409 Conflict
  (previously would have 500'd on these new rule violations), consistent with
  how Confirm/Reject/Cancel already handle it.

  Tests — new Appointments.Api.Tests/Tests/AppointmentBusinessRulesTests.cs, 11
